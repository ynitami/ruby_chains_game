### 基本ルールに関するFAQ

**Q: 「主力」「ユーティリティ」カードは引数なしでの呼び出し、「ジェネレーター」カードは固定引数での実行とありますが、どう違いますか？**

A: 以下のように区別されます。
* **主力・ユーティリティ** (例: `.chars`, `.to_s`): プレイヤーが引数を指定せず、Rubyで `( )` をつけて呼び出す（または `( )` を省略して呼び出す）形で使用します。
* **ジェネレーター** (例: `.scan(/../)`): カードに記載されている固定の引数（この例なら `/../`）を使って実行されます。
どちらの場合も、プレイヤーが任意に引数を変えたり追加したりすることはできません。

**Q: 「切り札」カードを「単体で出す」場合（例: `.map`）、どういう挙動になりますか？**

A: Rubyで `{ |it| it }` というブロック（引数をそのまま返すブロック）を渡した時と同じ挙動になります。
* `.map` の場合: `.map { |it| it }` となり、配列の要素をそのままコピーした新しい配列を返します（例: `[1, 2, 3]` → `[1, 2, 3]`）。
* `.group_by` の場合: `.group_by { |it| it }` となり、要素自身をキーとしてグループ化します（例: `[1, 2, 1]` → `{1=>[1, 1], 2=>[2]}`）。

**Q: 「切り札」カードを「Proc引数と共に2枚で出す」場合（例: `.map` と `.to_s`）、どんなカードと組み合わせられますか？**

A: Rubyの `&:` 記法（シンボルをProcに変換する記法）として有効なメソッドカードと組み合わせられます。
* `.map(&:to_s)` や `.map(&:size)` のように、**引数を取らないメソッド**（主に「主力」や「ユーティリティ」カテゴリのカード）が対象となります。
* 「ジェネレーター」カードのように固定引数を持つカードは、この方法（`&:` 記法）では使用できません。

**Q: ラウンドの最初から誰もカードを出せず、全員が「パス」をしたらどうなりますか？**

A: そのラウンドは「**勝利者なし**」で終了します。
* ダメージ計算（6.1）は発生しません。
* 捨て札処理とドロー（6.2, 6.3）は通常通り行います。
* 次のラウンドの開始プレイヤーは、その「勝利者なし」ラウンドで**最初にパスを宣言したプレイヤーの、次のプレイヤー**となります（6.4）。

**Q: ラウンド勝利者が、要求カードのお題を「両方とも」達成しました。ダメージはどうなりますか？**

A: お題を両方達成した場合でも、勝利者以外の全員が受けるダメージは **LPに4ダメージ** です。

**Q: 共通山札（レシーバー山札・要求カード山札）がなくなったらどうなりますか？**

A: ラウンド終了処理（6.4）の際、もし山札が尽きていたら、それぞれの**捨て札置き場にあるカードをすべて集め、よくシャッフルして新しい共通山札**とします。その後、通常通り新しいカードを1枚めくって次のラウンドを開始します。

ご指摘の通りです。私の説明が不正確でした。「一時的に有効」という表現は、まさにご指摘の通り「Aの可能性もBの可能性もある」という `.sample` の本質と矛盾します。

ゲームマスターとして、裁定を修正します。
`.sample` がプレイされたチェーンは「有効」でも「無効」でもなく、**「判定未了（Pending）」**の状態にある、と扱うのが最も正確です。

**Q: `.sample` のように、実行するたびに結果が変わるメソッドを使いました。チェーンの扱いはどうなりますか？**

A: `.sample` が含まれるメソッドチェーンは、その時点では「有効」とも「無効」とも判定されません。それはエラーの指摘やコードレビュー（※上級ルール）をしない限り、**「結果未確定（＝Aの可能性もBの可能性もある）」**の状態のまま、ゲームは進行します。

**Q: `.sample` が含まれるメソッドチェーンについて、エラーの指摘やコードレビュー（※上級ルール）をした場合にどう判定しますか？**

A: エラーの指摘やコードレビューの要求があり、`irb` での確認が必要になった場合、**その時点で `irb` を1回だけ実行します**。

1.  判定の要求: 他のプレイヤーが「`.sample` の結果次第でエラーになる（またはお題を達成できない）」と指摘します。
2.  `irb` の実行: 要求に基づき、該当チェーン（または `.sample` の部分）を `irb` で**1回だけ**実行します。
3.  結果の確定: その1回で出た結果（例: `5` が返った、`"a"` が返った）が、そのラウンドにおける**唯一かつ絶対の真実**として扱われ、それを基にエラーの有無や要求の達成/未達成を判定します。
4.  再判定の禁止: 一度 `irb` で結果が確定したら、誰もその結果を覆したり、再実行を要求したりすることはできません。

例（上級ルール）:
* 勝利候補者のチェーンが `[1, "a"].sample.upcase` だったとします。
* レビュー挑戦者が「`1` が返ったらエラーになる！」と指摘します。
* `irb` を1回実行します。
    * **もし `1` が返ったら:** `1.upcase` は `Error`。**指摘成功**です。勝利は無効になります。
    * **もし `"a"` が返ったら:** `"a".upcase` は `"A"`。**指摘失敗**です。挑戦者がペナルティを受けます。

### 🚀 上級ルールに関するFAQ

**Q: 「バーストチェーン」を宣言したものの、結果的に3枚以上カードを出せなかったり、お題を達成できませんでした。どうなりますか？**

A: 宣言を「撤回する」ことができます。
撤回した場合、出そうとした（仮置きした）カードはすべて手札に戻り、ターンをやり直します。 この撤回自体に対するLPやKPのペナルティはありません。

**Q: バーストチェーンの宣言時に、文法的なエラー（例：Arrayに.chars）が含まれていることに気づきました。どうなりますか？**

A: エラーの有無はラウンド終了時の「コードレビュー」フェイズで判定されます。宣言と実行の時点では、エラーがあってもチェーンは成立したものとして扱われます。

**Q: 「ラストチャンス」の「コードゴルフ」で、複数のプレイヤーが同じ「最少枚数」で達成しました。誰が勝利候補者になりますか？**

A: ルール（6. ラウンドの終了）に基づき、「**プレイ順が早い**」プレイヤーが勝利候補者となります。ラストチャンスのターンはバーストチェーン宣言者の次のプレイヤーから時計回りに回るため、より早く（宣言者に近い順番で）達成したプレイヤーが優先されます。

**Q: 「コードレビュー」を要求する際、チェーンのどの部分を指摘できますか？**

A: 勝利候補者がそのラウンドでプレイした**メソッドチェーン全体がレビュー対象**です。ただし、指摘する際は、以下の**いずれか一方**を**具体的**に指摘しなくてはなりません。
1.  **バグの指摘:** 「チェーンのどの部分が、どのオブジェクトに対して実行時エラーになるか」
2.  **要求未達の指摘:** 「チェーンの最終出力が、なぜ要求カードのお題を達成していないのか」
「なんとなく動きがおかしい気がする」といった曖昧な指摘はできません。

**Q: 「コードレビュー」の「追加ペナルティ」（エラー直前でお題を達成していた場合）とは、具体的にどういう状況ですか？**

A: これは、「**お題を達成したにもかかわらず、余計なメソッドを繋げてエラーになった**」場合に適用されるペナルティです。
* **例:** お題が「`Integer`の`Array`にせよ」
* **レシーバー:** `"1,2,3"` (String)
* **勝利候補者のチェーン:**
    1.  `.split(',')` → `["1", "2", "3"]`
    2.  `.map(&:to_i)` → `[1, 2, 3]` (この時点でお題達成！)
    3.  `.chars` → **エラー** (`Array`に `.chars` は呼べない)
* この場合、エラー（ⅲ）の直前（ⅱ）の時点でお題を達成してしまっているため、基礎ペナルティ（LP 2ダメージ or 手札1枚捨て＋ドロー1枚）に加え、**さらにLPに2ダメージ**を受けます。
